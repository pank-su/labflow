# Улучшения Labflow

## Подготовлено в этой версии

### Соразмерный workflow

- Полная работа и публикационный кандидат требуют независимого review.
- Локальная правка текста/оформления проверяется по затронутым страницам и зависимостям, без перезапуска несвязанного кода.
- Неприменимая фаза получает обоснование, а не выдуманный артефакт: CSV не превращается в PDF, теоретический ответ — в программу.
- Для автоматических запусков добавлено правило дешёвой проверки входов до тяжёлых фаз; для пакетов — отдельный результат каждого элемента. Это инструкции оркестрации, не новый планировщик.

### Контракт результата до сборки

`labflow-context` фиксирует источник каждого требования, точный шаблон, аудиторию,
выходные файлы, нотацию, единицы, отображаемую точность, примеры вычислений и
границы правки. Добавлен [шаблон контракта](../skills/labflow-context/templates/artifact-contract.md).

Служебные заметки и проверочные логи остаются во внутренних артефактах. В отчёте
сохраняются обязательные ссылки и ограничения, существенные для интерпретации
результата. Вывод отвечает на задачу, а не перечисляет действия агента. Требования
к размеру таблиц не переносятся автоматически между разными видами работ.

### Более строгая проверка SELF_REVIEW

`check_self_review.py --require-passed` теперь отвергает:

- пустые разделы, повторяющиеся обязательные заголовки, контракт в комментарии или кодовом блоке;
- отсутствующие/пустые таблицы требований и выполненных проверок;
- непрошедшие требования, проваленные или пропущенные проверки;
- незакрытые замечания и блокеры при итоговом `passed`;
- противоречивые или неоднозначные итоговые строки.

Для команды требуется код выхода `0`; для реально выполненного инструмента,
который не возвращает код выхода, предусмотрено значение `not_applicable`.
Это не разрешение пропускать проверку. Старый вызов без `--require-passed`
сохраняет проверку формы для чтения отрицательных review, но не даёт допуска.

**Граница проверки:** это валидатор структуры и явно записанных статусов.
Он не доказывает правдивость review, не открывает ссылки на логи, не проверяет
содержимое PDF и не связывает автоматически review с хешем кандидата.
Родительский агент обязан проверять эти свидетельства отдельно.

### Защита точки входа Typst

Инициализатор отказывается работать внутри каталога с `.labflow-protected`
или маркером совместимости `.guap`, в том числе в подкаталоге и с `--force`.
Он не изменяет правила вузовского шаблона и не заменяет его специализированный
генератор. Это защита штатного workflow, не sandbox. Шаблоны без маркера
по-прежнему должны распознаваться агентом при выборе адаптера.

В инструкции явно указаны версия Python, зависимость PyYAML для YAML-входа
и вариант JSON без PyYAML.

## Следующие дополнения — ещё не реализованы

### P0. Машинный паспорт кандидата и review

Один формат для списка входов/выходов, SHA-256, области проверки и статуса
независимого reviewer. Паспорт создаёт доверенная сторона до review, а не сам
reviewer. Список файлов включает нетрекаемые исходники и доставляемые PDF;
review-owned артефакты исключаются из циклического хеша.

**Приёмка:** изменение любого входа/выхода, пропавший файл, прерванный review,
неизвестный статус или устаревший fingerprint блокируют публикационный допуск.
Проверяющий файл не должен сам назначать авторитетный scope или expected hash.

### P1. Проверяемая привязка производных материалов к источникам

Для задания, таблицы или учебного вопроса хранить исходный документ, его хеш,
страницу/формулу и допустимую трансформацию. Отсутствие нужного источника —
блокировка, а не повод заменить его похожей темой. Сначала расширить общий
контракт, не копируя внутрь ядра реализацию lecture/practice adapters.

**Приёмка:** для каждого элемента можно найти конкретный исходный фрагмент;
изменение источника инвалидирует производный пакет; чужая нотация выявляется
проверкой, а не после выдачи.

### P1. Возобновляемые пакеты и дешёвое обнаружение изменений

Сохранённый per-item ledger с состояниями `ready`, `blocked`, `failed`,
`skipped` и `delivered`, причинами и source hashes. Отдельно различать «проверка
наличия выполнена» и «запрошенный артефакт готов». Источники, которые могут
поступать независимо, не блокируют друг друга без требования контракта.

**Приёмка:** повторный запуск не дублирует готовые результаты, но возвращается
к заблокированным после появления входа; не теряет частичный успех; no-op
не запускает OCR, сборку и reviewer. Ошибка доступа не считается no-op.
Конкретные cron, Apple Notes и доступ к кабинетам остаются вне ядра.

### P1. Профили оформления по виду работы в адаптерах

Отдельные правила для физической лабораторной, краткой расчётной работы,
курсового проекта и учебного конспекта: разделы, таблицы, примеры и выводы.
Приоритет имеет текущая методичка и явная пользовательская поправка.

**Приёмка:** профиль физлабы не меняет автоматически шрифты краткой расчётной;
образец переносит структуру/стиль, но не устаревшие данные и текст.

### P2. Регрессионные сценарии всего workflow

Проверять не только строки в SKILL.md, но и наблюдаемые действия: bounded edit,
CSV без PDF, недоступный обязательный источник, две независимые заметки,
частичный пакет, остановка во время review, изменение кандидата после review.

**Приёмка:** для каждого сценария заранее заданы разрешённые действия, выходные
файлы, состояния и запрещённые ложные утверждения. Все fixtures синтетические;
частные диалоги и учебные материалы не включаются.
